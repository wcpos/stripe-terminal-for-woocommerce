**Stripe Terminal for WooCommerce 2.0.0 requires WooCommerce POS Pro 2.0.0 or newer.**

This is the 2.0 version of Stripe Terminal for WooCommerce, made for WooCommerce POS 2.0. Without Pro 2.0.0 the plugin does nothing and shows an admin notice. Stripe Terminal is no longer offered on the shop's web checkout; it takes payments in the POS only.

## What you need to do

- Update WooCommerce POS and WooCommerce POS Pro to 2.0.
- After updating, open WooCommerce > Settings > Payments > Stripe Terminal and save the settings once with your Stripe secret key. This registers the POS webhook with Stripe. The settings page shows "Signing secret stored." when it is done.
- If you use Bluetooth readers or Tap to Pay, choose a **Terminal location (testing)** and **Terminal location (live)** on the same page.

## What changes

- A store can now run smart readers and the app's readers at once; each till pays with the reader it selects. Tick the kinds of reader your store allows under **POS connections**. Your saved setting keeps its meaning.
- Bluetooth readers (Stripe Reader M2, WisePad 3) and Tap to Pay on iPhone and Android take payments in the WooCommerce POS 2.0 mobile app. Web and desktop tills use smart readers.
- New settings for smart readers: **Default terminal**, **Enabled terminals** and **Lock terminal selection**.
- On-reader tips you set up in the Stripe Dashboard are added to the order as a Tip fee.
- The POS Legacy tab (the order-pay page) now runs through WooCommerce POS Pro's shared order-pay panel, so its payments refund from the till like a keypad payment. With **Phone Orders (MOTO)** on, Stripe's own panel stays.
- Web checkout is gone, along with the "Enable Stripe Terminal for web checkout" setting. If you had it on, nothing changes in the POS.
- Retries are safer. A payment whose request Stripe did not answer stays pending and resumes on the same payment when the till retries. A refund in the same state is sent again under the same key, so the customer is not refunded twice.
- A refund that Stripe marks as pending shows as confirmed or rejected on the order once Stripe settles it.
- The plugin ships its own copy of the Stripe PHP library, so another plugin that bundles a different version no longer causes a fatal error.
